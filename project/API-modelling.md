## Notes - Guidelines (taken from [here](./readings/[2018-Hippehen]Designing_Microservice-based_Applications_by_using_a%20_DDD_approach.pdf) Pianini/Ciatto read suggestion)

**Web APIs should adhere to the following informal quality criteria:**
1) they should be easy to understand learn and use from a service consumer’s point of view
2) they should be abstracted from a particular technology
3) they should be consistent in look and feel
4) they should be robust in terms of evolution.

To structure standardized API following [OpenAPI](https://swagger.io/docs/) specifications.

**API Design**

''*For deriving the web API, we considered each view regarding the represented information as well as the interaction elements used for data manipulation. This approach allowed us to build resources, their representations and the necessary operations. The resulting web API is highly linked to the UI and must be connected to the underlying domain represented by microservices.*'' [pag. 8 - [2018 - Hippehen B. et al.] Designing Microservice-based Applications by using a DDD approach]
